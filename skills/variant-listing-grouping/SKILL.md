# 综合链接变体归组 + 试上链接草稿

原则：同一个产品的不同尺寸、不同颜色，上到**同一条综合链接**做成变体，不要拆成多条链接。

## 归组判断
1. 常见 SKU 规律：**前缀 = 尺寸，后缀 = 颜色，中间核心码相同 = 同一产品**。
   - 例：`13-XXXX-Brif-PK` 与 `N14-XXXX-Brif-PK` → 同品不同尺寸；`13-XXXX-Brif-PK` 与 `13-XXXX-Brif-ORG` → 同品不同颜色。
2. 这只是大概规律。品名、图片或总表看起来像同一产品、但 SKU 看不出来的，**列出来问老板确认，确认前不要自己归组**。
3. 用 ERP（如领星）产品表和总表交叉核对品名、尺寸、颜色。

## 试上链接流程
1. 从「建议新增」清单里先挑 1 个产品试做。
2. 列出该产品所有变体：SKU、尺寸、颜色、品名、库存、参考价。
3. 过滤：
   - 跳过总表里标为「计划下架/已下架」的 SKU。**先确认标记到底是字体颜色还是单元格底色**，并把「被跳过但仍有库存和销量」的单独列出来问。
   - 只保留库存达标的变体。
   - 查现有店铺链接，确认核心码没有重复上架。
4. 价格按店铺既定公式计算（公式由老板定，写明取价日期）。
5. 产出本地草稿（xlsx + md 摘要）：归组、标题文案、变体表、属性、图片 brief、待确认问题清单。
6. **只做本地草稿，不动后台、不碰现有价格**；老板确认后再上架。

## 坑
- 不要因为 SKU 规律对上就默认归组，例外很多。
- 标题里的材质等属性以权威详情页为准，发现平台标题写错要标出。
