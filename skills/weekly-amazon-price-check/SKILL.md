# 每周亚马逊对价与 SKU 对齐

每周对照亚马逊 US 现价，给跟它对齐的店铺（如 TikTok Shop）出调价、建议上架、建议删除清单时使用。只出提案，老板没批之前不改后台。闪购和叠加优惠不在本流程里，见 `tts-promo-pricing`。

## 定价与清单规则

- 目标原价 = 采用的亚马逊现价 × 2 + 10（按团队定价规则替换）。
- 现原价与目标价差在 ±5% 内算已对齐，不进调价清单；超出的进清单，按差额%从大到小排，每行写清：旧原价 / 亚马逊新价 / 建议的新原价。
- 亚马逊 US 有、本店没有的 → 建议上架；亚马逊已停售（页面 404 / Currently unavailable，且状态、价格、库存字段也支持）→ 建议删除。删之前核对本店库存，有货的标「删前请确认」。
- 红线：本店原价必须高于亚马逊现价，不能倒挂或低到影响亚马逊价格。接近或低于亚马逊现价的标为危险价，单独列出。
- 改价、上架、删除都只出清单，等老板批了再动。

## 节奏

- 跟亚马逊总表的周更走，全量对一次即可（当前例行是北京时间周二上午）。不要每日全量爬亚马逊页面。
- 促销季，或上次活页价与表价不一致时，用页面抓取抽查销量靠前、或上次不一致的链接（例如 Top 50），每周 1–2 次，不必全量。

## 怎么取亚马逊价

- 不要用 curl / 脚本直接打亚马逊域名，容易被验证码拦死，不能当日常任务。抽查用 WebFetch（或同等页面读取）。
- 只取买盒价 / One-time 现价，不用划线 List Price，不用 Amazon Resale 价。没有买盒、库存状态不清的，保守跳过，不采用该价。
- 全量表价以 ERP（如领星）和亚马逊总表 / 库存表交叉核对，写明每个数据源的快照日期和店铺 / 品牌口径（只用老板确认过的口径）。
- 在领星里取亚马逊现售价：左边「销售」→「Listing」（有的界面写成「在线商品」），列表里的「价格」是后台 Your Price，也是对价用的现售价；有促销再看「优惠价」或「售价（总价）」。不要用划线的 List Price。不要走进「销售」→「平台商品」→本店所在平台，那是本店原价，不是亚马逊价。站点 / 店铺口径只用老板确认过的。
- 两个数据源差 ≥ $0.50 或 ≥ 5% 的行单独标出。确认映射、以及表里的 Price 是否就是自营现价之前，不要按有争议的源价批量调。
- 不要把本店总表里未确认的「US售价」「TK售价」当成亚马逊现价或本店原价。本店原价以后台为准；只有过期快照时，摘要里写明时点，并声明「这不是实时调价清单」。
- 判断亚马逊是否有价、是否停售，只看亚马逊的状态、价格、库存字段和实时链接，不要用表格颜色图例。

## 相对上周

- 交付时先让老板看「相对上周变动」，再看「调价清单」和「活页抽样」。
- 若本周改了数据源优先级或口径，由此产生的价差要单独说明，不要写成「亚马逊涨了 / 跌了」。口径没变、采用价仍差很多，才算实质变动。
- 记录各清单的进出（新增 / 移除），不要只报总数。

## 活页抽查

- 计划抽哪些、实际完成哪些、未抽到（没来得及）和抽样失败（抓取失败）要分开记，别混称「失败」。
- 活页买盒价与表内采用价差 ≥ $1 的标出；活页不可售但本店仍在售的，列入建议删除（有库存则警告先确认）。
- 活页证实了某条偏低的表价，只说明「页面现价如此」，仍须按上面的数据源规则决定能不能批量采用，不要据此一刀切。

## 交付

- 一个 Excel：摘要（口径、时点、假设、未知）、相对上周变动、调价清单、建议上架、建议删除、未匹配、活页抽样。
- 一段中文摘要：对齐 / 待调各多少、危险价、数据时点、哪些变动来自口径而非真涨跌、活页结论。
- 全程只读：未批准不改价、不上架、不删除。
