# 全店诊断（只读导出 + 四部分分析）

## 红线
- 全程只读：只看、只下载导出，不改价格、链接、活动、库存。
- 后台活动页避开 Duplicate / Create / 发布类按钮。误点进新建页时：不发布、不做验证码、直接返回，再只读翻查活动列表（所有状态）确认没有生成新活动或草稿，并主动告诉老板。
- 拿不到的数据标「未知」并写原因，不编数字、不用官方费率去填缺口；推断写成「假设」等老板确认（例如哪个亚马逊店铺算「我们的」，可用 SKU 重合率佐证）。
- 老板没说要初版就做完一次性交；中途只报进度和阻塞。

## 1. 数据清单（先导再算）
- 周期四档：近 1 年、半年、3 个月、1 个月。先试近 1 年能不能一次导全，不行再分段。
- 后台：产品级 + SKU 级分析表（曝光、CTR、加购、转化、件数、GMV、退货、库存状态）、订单列表、结算明细（含各项费用列）、活动/促销清单。
- ERP（如领星）：亚马逊价（主口径）+ 本地总表价（交叉核对）、可用库存。
- 写一份 data_inventory：每份文件的来源、日期范围、快照日期、时区（结算常是 UTC-8，订单可能没标）。

## 2. 价格合理性
- 目标价 = 采用的亚马逊价 × 2 + 10（按团队定价规则替换）。
- 现售价与目标价差 ±2% 内算对齐，超出算偏高/偏低，缺值标未知。
- ERP 价和总表差超过 $1 或 2% 的行单独标出。
- 「对价待复核」：采用价 < 0.7 ×（现售价 − 10）÷ 2（即低于由现售价反推的亚马逊价的 70%），或两个数据源相差 > 30%。别用「采用价低于现售价 40%」这种字面规则——现售价本来约是 2 倍，会几乎全部命中。
- 可疑行先查匹配：SKU 原样匹配、两边 ASIN 一致、Price/List Price/总表三价是否一致。都一致时问题在亚马逊在低价冲量，参考价按现价还是历史价/同父体价交老板定。
- 优先处理：差额大且近 30 天有销量的；库存为 0 的和补货一起看，不要单独改价。

## 3. 折后回款
- 一律用结算实数：订单行与结算按 Order ID + SKU ID 匹配，按下单日落入各周期。
- 拆解：毛销售 → 卖家折扣 → 折扣后货款 → 净销售 → 实收；分列推荐费、达人佣金、平台推广费、运费及履约。
- 用实测推荐费率（推荐费 ÷ 折扣后货款）核对官方费率并写明出处和日期。
- 未结算订单（近期已发货/待发货）标「实收未知」，不当成 0；记录匹配率。
- 结算报表合计与行加总对一遍，差额应为 0。
- 留意：实收为负的 SKU（多半是履约方式问题）、达人佣金超过推荐费、折扣力度过大。

## 4. 滞销/低销归因
- 阈值事先写明、事后不改，用 30 天在售商品分位数：低曝光 = 曝光 P25；低 CTR / 加购率 / 转化 = 有一定流量商品的 P25；高退货 = 有销商品退货率 P75 与 15% 中的较高者；低销 = 30 天件数 ≤ 某个上限。
- 主因按固定顺序判：已下架 → 缺货 → 低曝光（流量不足）→ 曝光正常但 CTR 低（主图/价格展示）→ CTR 正常但加购/转化低（价格、详情、评价、变体）→ 漏斗未跌破阈值（季节/需求小）。指标缺失标未知，不硬归类。
- 每条给依据（具体指标值）和具体动作：CTR 低先换前 3 张主图、看价格展示；转化低对照目标价、查详情图是否讲清尺寸/兼容机型、先读退货原因、零销变体移出综合链接；已下架先确认还卖不卖。
- 可估算流失 GMV（标明是估算，不是实收）用于排序。

## 5. 断货补货
- 纳入：365 天或 180 天有销量，且 ERP 可用库存 = 0 或平台显示 Out of stock。两边打架标「先核对库存」，不要直接下采购单。
- 列 365/30 天销量、最后出单时间、价格标记、亚马逊库存。
- 分档：建议补货（近期仍出单、趋势稳，按近 90 天日均小批量补）/ 小补观察（趋势下滑或近 30 天无单）/ 暂缓 / 不建议（近 90 天无销量或已下架）/ 先核对。价格偏高的先定价再备货。

## 6. 核对与交付
- 每部分随机抽 20 行对回后台原始导出，写进 spotcheck 记录；对不上就标出，不硬填。
- Excel：说明（口径、阈值、假设、未知）+ 四部分各一张 sheet，按优先级排序、用颜色分档。
- 中文摘要 md：先看数字、每部分最该做的 5 件事、未知与待确认清单。
