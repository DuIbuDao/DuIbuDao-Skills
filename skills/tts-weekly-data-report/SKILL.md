# TikTok Shop 每周数据周报

## 时间口径（最容易错）
- Seller Center 按美西时间出数：某一美西日的数据，要到该日在美西结束后才完整，即**北京时间次日 16:00 以后**。周报因此定在周一 16:30 开跑、17:30 前交；早于 16:00 导出的版本最后一天是残数，不要用。
- 周中补数也一样：北京时间某日上午导出时，最新完整美西日是前天，完整近 7 天是「前天往前 6 天」至前天。不要把还没结束的美西「昨天」算进去。
- 范围：上周一至周日；目录用运行当天的周号 `<YYYY-WW>`，原始导出放 `<周>/raw/`，加工结果放 `<周>/`。
- 依赖别的岗位的输入（如客服的售后/差评周报、独立站导出）要早于周报开跑时间交，到不了就先出主表，之后补并。

## 导出（只读，只下载）
1. Data Compass 导出整周的商品表、SKU 表、达人视频表、达人表；能导的广告数据一起导。
2. 每个文件导完核对**表内日期范围和行数**。后台文件名、路径里的日期是导出当天或人工命名，不是数据日期，以表内为准。
   - 有的表（尤其达人表）里面没有报表日期字段，**文件本身不能独立证明统计期**。必须另有导出当时的日期范围记录；不能凭文件名把旧表当成已经补齐的缺日，也不能把旧表最后一天误报成后台当前可取上限。
   - 数行数时去掉说明行和表头，不要把表头算进业务记录数。
   - 页面上看到的可取截止日，要等实际导出核对后才写进结论。
3. 已知的坑，照实标注、不估算：
   - 视频表、达人表常比商品表少最后一天 → 标「缺 X 日」。
   - Ads / GMV Max 页可能没有导出按钮 → 标「未导出」。
   - 导出里没有 3 秒留存、SKU 级曝光/CTR/CTOR、达人表没有商品列 → 标「导出无此字段」。
   - 视频表通常有达人、商品 ID、发布日期和视频级成交/退款，但往往没有卖家 SKU；能映射上 SKU 的比例要报出来，对不上的不要猜。
   - **一条视频挂了多个商品时，不要把该视频的 GMV/单数拆到各商品上再加总**——多商品如何归因未经证实，拆开会重复计算。
   - 达人表里的 Samples shipped、Total sample content 只是计数，不是寄样日期；视频发布日期也不能当寄样日期。没有实际寄样日期就标「导出无此字段」，不要推算。还没打开页面核对过的报表，不要断言「后台不支持」。
   - 达人视频表要核对来源是店铺达人带货视频，不是官方账号作品列表。导错了隔离存放，不用于达人表或钩子/形式分析，也不用上周数据顶替。
4. Data Compass 报 "Something went wrong" 或白屏：最多重试 3 次；整个内容区都空，多半是店铺网络或代理那台电脑离线，原样报错，不点「智能修复」、不改代理设置。
5. 自己没有后台账号的岗位，请有账号的岗位代导到共享 raw/，代导方回报：路径 + 表内日期 + 行数 + 缺了什么。可设成每周固定时间（16:00 后）自动代导，账号开好后再停。

## 加工
- 商品/SKU 对上 ERP 的 SKU 映射，报对上比例；对不上的单列，不猜。
- listing 表固定几张 sheet：`top10_by_gmv`、`worst_converters`（曝光 ≥1000，按 CTOR 从低到高）、`high_refunds`（期间退款件数/期间卖出件数）。这是同一统计期内的件数比，不是同一批订单的退货率；汇报时写清楚，不要说成同批次退货率。
- 售后和 1–3 星差评按 SKU 挂到 listing 表；没有 SKU 的留空，不按标题猜。
- 环比：只有拿到不重叠的上一整周才做。30 天/7 天滚动数据和本周重叠，不能拿来算环比，第一周直接写「无环比」及原因。某张表缺日或只有残周期时，该表不做环比。
- 达人视频：把「期内新发」和「期前老视频」的出单分开列，否则老视频的单会掩盖新钩子的效果。转化用「每千次播放出单数」横比品类。

## 交付
- 文件：`listing.xlsx`、`video.xlsx`、`creators.xlsx`（+ 其他渠道表）放进 `<周>/`，分别发给 Listing、视频、BD 等岗位，各附 2–3 行要点。
- 给老板/经理的摘要 ≤5 行：全店 GMV/单数/件数；GMV 第一的商品；最该盯的 1 条（典型是曝光最高但 CTOR 很低且退款高）；缺数清单；有没有环比。
- 任何拿不到的数写「未导出 / 未授权 / 缺 X 日」，绝不编数、不用估算填。
