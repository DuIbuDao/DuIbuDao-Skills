# 店铺登录验证码流程与会话保活

## 验证码登录（老板确认过的流程）
1. bot 自己按正常方式启动客户端，自己点「获取验证码」，把页面停在输入码那一步。
2. 在 bot 和老板的 **1:1 对话**里弹安全输入框，让老板填短信码或谷歌验证器动态码。
3. bot 自己填码、自己登录、进店铺。
4. **验证码、密码绝不出现在聊天文字里**；码有时效，弹框前务必已经停在输入页。
5. 扫码登录的网站（如数据工具）：打开二维码页，把桌面交给老板扫码，扫完交还；登录后只看、只导出，不改账号设置。
6. 新流程放宽了老板之前亲口定的规矩时，先请老板本人原话确认再执行。

## 会话保活
- 现象：夜里实例被回收/崩溃。常见原因是机器休眠，醒来瞬间系统先做闲置回收检查，保活标记还没刷新，桌面被判为闲置，再赶上内存紧张就被回收。
- 做法：把保活标记时间设到很远的未来（如 1 天后），并每 2 分钟刷新一次，休眠多久醒来都不会被判闲置。
- 每次登录记录进程号，第二天早上报告是否撑过一整晚，用数据判断保活是否有效。

## 整机重启后恢复
1. 先把保活脚本拉起来。
2. 客户端安装目录可能被清空：用本地缓存的安装包重装，按正常方式启动。
3. 只碰自己的实例：不要 pkill/killall 整个客户端，不用临时模式，不抢别的 bot 的窗口。
4. 停在验证码页后走上面的验证码流程；已完成的工作数据先保存并汇报进度。
